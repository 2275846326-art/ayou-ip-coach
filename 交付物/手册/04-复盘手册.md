# 04 · 复盘手册（任务手册）

> 数据回来后，判断"这批做得对不对、下一步改什么"。复盘不为总结，为改下一条。
>
> 机制来源：对赌契约（参考 ip-strategist 契约复盘机制改造）；判断框架来自《真需求》价值/分歧/归因 + 通用数据复盘逻辑。

## 本任务解决什么

用户粘来一批数据（播放/点赞/评论/转粉/完播），问"怎么样/怎么办"。目标是：**逐条验证当初的赌注，归因，定下一步改什么。**

## 先立规矩：三条硬纪律

1. **至少 3 条一起看**，单条有偶然性。拿一条爆/扑来问=把偶然当规律。
2. **每批只换了一个变量**才可能归因（当初契约里写的"控制变量"）。两条就下结论是最常见错误。
3. **盯局部比值，不盯总播放**：总播放波动因素太多。看波赞比、赞粉比、完播曲线异常点。

## 复盘四步

### 第一步：粘数据（缺什么直说）

至少要：播放、点赞、评论、分享、新增关注；有则补：完播曲线异常点、点赞分布、评论前 20 条内容、新粉头像抽样。

> 平台拿不到的数据标"未知"，不估算伪造。

### 第二步：逐条对赌注（核心动作）

拿出当初签的契约，一条条问：赌什么 → 数据支不支持 → 标 ✅已验证 / ❓待验证 / ❌已证伪。**每条必写原因和数据依据，不许写"看起来还行"。**

对照维度（来自契约与内容手册）：
- 需求戳中了吗？（看评论在讨论什么——是不是你赌的那个点）
- 钩子焊住前 2 秒了吗？（完播曲线前段）
- 骨架撑住中间了吗？（完播异常点——**第 N 秒掉，问题往往出在第 N-2、N-3 秒**，倒推）
- 主验证目标兑现了吗？
- 反事实兑现了吗？（扑街的话，锅在不在你猜的地方？）

### 第三步：归因（这是全部价值）

**数据指向 A，不代表 A 就是对的答案。数据是线索，不是判决书。** 追到真因：
- 完播第八秒掉 → 别急着改第八秒 → 倒推是不是第五六秒说了句让人反感的话。
- 播放高不转粉 → 不是"关注按钮"问题 → 查：人群错？未来价值弱？主页承接断？记忆资产缺？（增长四问：为什么停下来/当前价值/未来价值/主记忆资产）

### 第四步：沉淀 + 定下一步

- **沉淀**：结论写回档案认知沉淀区——A 轨（内容打法管不管用）/B 轨（对这个人认知，在哪被打脸）。**同一判断验证 ≥3 次才下重结论**；已证伪的最值钱，必写原因。
- **下一步只改一个变量**：下一批 3-5 条，只换那个被怀疑的点，其余九成保持不变。

## 反模式（看到就停）

- **凭感觉复盘**："整体还不错，继续加油"——最废的四个字。
- **只盯播放量**：用错的尺子量对的东西。
- **契约偷偷改**：复盘时把当初判断改顺一点再"验证"——改完当然容易验证，但复盘失去意义。契约冻结，要改就新开。
- **只记对的**：证伪的悄悄丢了=同样的错下次还犯。**诚实的证伪比漂亮的验证值钱一百倍。**
- **把复盘当走过场**：为应付提醒随便粘数据=在档案里写假数据，污染后续所有判断。

## 交付物

1. 结论：这批做对了什么 / 哪条赌注被验证 / 哪条被证伪（带数据）
2. 归因：真因是什么（不是表面数字）
3. 下一步：下一批只改的一个变量 + 验证目标
4. 沉淀：一句话结论（进 A 轨或 B 轨，标验证次数）

## 交付前自检

- 是至少 3 条一起看的吗？变量控住了吗？
- 每条验证都写了原因和数据依据吗？
- 归因追到真因了吗（倒推过吗）？
- 下一步只改一个变量，明确吗？
- 证伪的记下来了吗？
