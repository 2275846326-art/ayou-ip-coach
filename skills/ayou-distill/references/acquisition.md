# 多源获取与长内容处理

## 路由

| 输入 | 首选入口 | 定位与限制 |
|---|---|---|
| TXT/Markdown | ingest | 原行号、标题路径 |
| PDF | ingest；涉及图表再查看对应页 | 阅读器页序/行号；扫描页需OCR，文字提取不等于看过画面 |
| EPUB | ingest | 按spine阅读顺序，章节文件/行号 |
| DOCX | ingest | 段落号、表格行号；图像与混合排版需复核 |
| SRT/VTT/字幕JSON | ingest | 原时间范围；不为分块自行插值时间 |
| B站/YouTube等视频链接 | ingest，使用yt-dlp的支持范围 | 先人工字幕、再自动字幕；默认zh/en；支持平台仍可能需权限或受限 |
| 网页/文章链接 | ingest，必要时浏览器/连接器读取 | URL、正文定位；JS/登录/反爬页不当完整原文 |
| 播客RSS | ingest读episode线索，再选具体集的transcript URL | 订阅简介不等于节目正文；无文字稿转到转写提供者 |
| 本地音视频、无字幕视频 | 可用转写提供者 | 当前工具报告needs_transcript，不虚称内置ASR |
| 课程/资料集 | collection逐份处理 | 每份独立来源和版本，按讲次/时间组织，不抹平冲突 |

链接是用户指定来源；书籍仍须使用用户指定底本。首次取材先记录标题、作者/讲者、发布日期（未知就标未知）、URL或文件路径、SHA256、实际取得的范围、人工/自动字幕、语言与画面核查状态。

脚本联网受到沙箱限制时按环境要求申请联网执行；失败如实报告，依次尝试已有连接器或浏览器、已提供文件，不不断重复同一路径。不要自动拿网络摘要替换失败的正文。

## 结果状态

- needs_review：取得可读材料，尚未核对来源语义/字幕准确性。
- needs_browser：网页文字过少或依赖页面交互，改用可访问浏览器读取。
- needs_episode_selection：找到节目清单/转写链接，尚未选具体来源。
- needs_transcript / needs_ocr / needs_dependency / acquisition_failed：清楚说明缺口。不得跳到“已蒸馏”。

无字幕媒体的完整衔接：如当前环境有 lark-minutes，读取它的 SKILL.md 和必需引用，按其授权与隐私范围走“上传媒体→生成妙记→读取原始逐字稿”；不拿AI总结代替原始发言。已经有用户许可则继续；向云端上传未获授权的私人资料先明确目的地并取得授权。无可用提供者时保留待转写，不自动安装本地ASR或猜测语音内容。

## 长材料与阅读覆盖

预处理目录是按来源ID和内容/解析参数哈希分版本的缓存，保存原始字节、document.json、chunks.json及校验manifest。重复同版本命中缓存；检测到手改不静默覆盖。来源变化生成新目录，旧版本保留。

分块是定位工具，不是内容理解。chunk保留原行/页/时间/标题，单块默认4000字符；超长记录按字符拆分，偏移单列，不捏造页码或时间戳。框架和原则须全量扫描，检索只用于找案例、反例和术语，并补看邻块。预处理全文不等于AI全文阅读。

在工作目录留 reading-ledger：来源版本、块ID、已读/未读、提取路线、三句话钩子。阶段结束对照全量关键任务，重要遗漏必须解释或补读。画面操作、图表、PPT、演示步骤依赖视觉时登记时间段和待核查画面；未查看的视觉结论不成为active能力。
