# 五路提取、关联与覆盖

先形成全局结构及使用目的，再执行五条互相区分的提取路线。默认由当前AI串行执行；只有用户/适用指令授权多代理时才并行，子代理也使用同一底本和版本。

| 路线 | 阅读方式 | 产出契约 |
|---|---|---|
| 框架 | 全量逐块扫描 | 决策框架/流程/排障；完整条件分支、输入输出、跨章节依赖，单处讲完整也保留 |
| 原则 | 全量逐块扫描 | 原则/清单/公式；变量、单位、条件、表格脚注，禁止只留口号 |
| 案例 | 检索＋邻块 | 来源实例与例题、它证明什么；故事类型、讲者转述与亲历分开，结果未知标未知 |
| 反例 | 检索＋邻块 | 来源失败场景、警告、局限和方法失效条件；我们的批评另列 |
| 术语 | 检索预筛＋回查定义 | 作者定义、相近概念区分、首次来源、跨版本译名差异；词频不是重要性 |

每路记录 candidates 文件，条目有稳定ID、source_id、chunk_id、原位置、论证、完整性缺口和建议去向。共同质检：来源充分、可执行、任务增益；各自理由留档，不因另一提取器选过就免检。

核查去向分能力、参考、待核查、淘汰。参考实际进入overview/glossary，待核查不编译。覆盖表从来源的关键任务出发，而不是只数通过能力；重要任务没有去向必须补读或说明未交付范围。

在 Bundle 为能力登记 `also_read`（相关能力ID）、`trigger`（语言和边界）、`one_liner`（决策速查）；梳理依赖、互补、对照与容易混淆关系，在能力卡里解释关系类型。工具会校验不存在/自引用并生成链接；依赖变更影响回归范围。

共享术语、内容总览可作为 `book_resources`，显式列出相对文件路径。资源如计算脚本、CSV/JSON模板放工作目录，能力的 `resources` 显式声明；随包只复制不执行，UTF-8文本可用，未声明的不打包。

人类DIGEST在最后基于已核查底座与能力写：主问题→方法→原案例/合成演练→失败条件→作者局限→如何用。应用扩展另标，长度按材料而定；不让短视频也硬凑长文。
