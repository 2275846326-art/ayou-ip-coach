# 蒸馏与 IP 知识系统的双向联动

这里的系统是用户已有的 **IP 知识系统**。AYOU 负责提供可追溯的知识和能力增量，系统负责在定位、选题、成稿、复盘、变现等工作中使用与反馈。每次实质蒸馏或更新默认走完影响判断；用户只要求摘要、章节地图尚未确认、底本尚未获取时停在对应阶段。

## 1. 接入现行系统

先定位当前权威底座、系统入口、任务手册、方法来源地图、仲裁记录及版本/发布协议。已有上下文就沿用，不让用户重复提供；找不到系统时继续蒸馏并交付待接入增量，不能声称已集成。

阿柚系统的相对布局：入口 `01-系统交付物/SKILL.md`，任务手册 `01-系统交付物/手册/`，原著蒸馏 `03-书蒸馏资料/`，技能源 `07-工作流/技能库/`。当前项目的 `方案A-执行协议.md` 与 `方案A-仲裁与变更记录.md` 定义裁决和流转。通过工作区入口或本地连接记录定位权威目录及协议；每轮核对真实文件与版本，迁移环境时重新发现，不凭旧路径假装读取。

按真实目录定位，不新建平行方法库：

| 蒸馏所得的用途 | 首先对照的现有模块 |
|---|---|
| 判断原则、取舍与方法冲突 | 00-心法与判断纪律、06-方法边界与来源地图及仲裁记录 |
| 用户需求、诊断与定位 | 07-问诊与诊断、01-定位 |
| 选题与核心观点 | 02-选题 |
| 论证、结构、表达 | 03-写稿、09-标题提炼、10-图文内容逻辑 |
| 视觉传达 | 08-封面制作；需要时衔接既有制作技能 |
| 数据解释、反例与验证 | 04-复盘及当前 IP 的契约/档案 |
| 产品、服务与收益机制 | 05-变现 |

本表是检索起点，不是自动判定。需要时直接读相应小节；导师融合、来源地图、检索索引、交付入口的真实依赖也列入影响范围。没有执行价值的概念仍可进入来源地图或六层参考。

## 2. 每次交付一个可审阅增量

在蒸馏任务目录生成 `ip-system-impact.md`，不得只说“可用于 IP”。最少记录：

- 增量 ID、父任务与版本、底本哈希、六层/能力 ID、核对范围及原文定位。
- **来源原意 / 应用扩展 / 待验证假设**分别记载；应用扩展说明如何从来源迁移到 IP 场景。
- 系统目标文件与小节、当前规则摘录、建议新规则、适用/不适用、改变的工作行为。
- 去向：新增 / 补边界 / 修正执行 / 与现行冲突 / 已有同义规则 / 暂不接入。冲突说明双方证据与取舍建议；同义内容合并来源，不再叠一套规则。
- 回归任务、实际输出与评审、效果证据状态、负责人裁决依据、发布分类及当前采用状态。
- 受影响的下游入口、手册、索引、运行副本和交付包；若无依赖则明确写无。

知识底座模式也做此检查；无需先编译 Bundle。核查不足的增量保留为待核查；没有适用增量时写“无系统更新”及原因。先查历史增量 ID/来源版本/目标规则，避免同一内容反复入库。

## 3. 来源核查、任务回归、正式采用分别留证

来源核查解决“作者到底说了什么”；任务回归解决“这条执行方法是否满足契约”；实际效果解决“在什么人、场景、条件下产生了什么结果”。三者不能互相替代。

回归优先复用系统已有任务；按本次影响补一个典型任务、一个不适用或缺证据任务，以及相关旧规则的保护案例。记录更新前后的实际输出和变化理由，不要求新版本为了显得更好而改所有输出；同一代理自评注明，未真实运行不填通过。商业效果未知就保持未知。

候选 → 已测试待裁决 → 已采用工作规则 → 有实际效果证据的经验，是不同状态。冲突、永久替代及通用规则升级按现行负责人裁决。具体任务的暂定使用不等于全局采纳。读取本次已有授权，已明确同意最终版本的事项直接执行，不重复申请同一授权；未决项先完成草案和测试，再仅就具体取舍提交负责人。

## 4. 写回与版本流转

来源与六层先保存到权威底座，正式方法按采用决定写回现有文件；引用来源位置，不把整本书再复制到手册。依赖同步在同一迭代中完成，不能只有手册改了而入口仍指向旧方法。

写入前重新核对目标父版本/哈希，保留旧快照，原子替换并回读；版本递增，记录 Parent-SHA256、增量 ID、采用依据与实际变更。父文件变化时重新对照，不能以较新时间戳强行覆盖。

可用工具留下基线并检查变化：

```text
python scripts/ayou.py ip-plan request.json --root <权威底座> --out ip-system-plan.json
python scripts/ayou.py ip-check ip-system-plan.json
```

request.json 格式：`delta_id`、`distillation_ref`（已存在的六层/蒸馏文件绝对路径）、`sources`（含 path、location、source_status）、`changes`（含 target，相对底座路径；section；before；after；change_type；evidence_kind；source_indexes；regressions）。change_type 为 add/boundary/execution/conflict；evidence_kind 为 original/application/hypothesis；source_status 为 verified/needs_review。source_indexes 是本条变更引用的 sources 数组下标。regressions 是计划任务与验收标准的文字数组，不是通过结果。Bundle 可选，能力 ID 可附在变更中。

工具要求现有目标文件；新增模块先由 AI 制作候选并人工核对路由。它只生成来源/蒸馏/目标的哈希基线并检查漂移，**不执行语义核查、不验证测试通过、不判定授权、不写回系统**。其成功输出仍是 candidate；正式写回执行上述流程或系统既有状态更新工具。

公开流转以现行协议为准：已决定系统迭代并认可最终可审阅版本后，完成底座、运行副本和可公开 GitHub 内容的同步与核验，不再重复问“是否推送”。客户档案、私人数据、付费课程原文不进入公共版；遇权限、网络或远端冲突保留本地结果并报告实际状态。手机附件是版本化快照，未更新附件不能声称手机已同步。

## 5. 系统反馈反向优化蒸馏

每条真实反馈关联任务 ID、IP-ID、系统版本、增量/规则 ID、执行是否偏离、观察与归因、原始证据及可共享范围。先区分触发/来源理解/方法边界/执行/评价/业务环境问题，不把一次失败直接判为方法无效。

需要修订时回到来源条目和能力卡，保留作者原意，修改应用扩展或提出待核查原意；补上失败案例与相邻任务回归，形成下一次系统增量。只影响一个 IP 的事实或偏好写入该 IP 档案；通用化需来源、适用边界及裁决，不把个人结果直接变成全局经验。遵从当前协议对多次观察与复审的规定，不自行设置“达到 N 次自动成为规律”。

任务完成报告：知识已保存的位置、系统增量及采用状态、实际修改/同步的版本、尚未执行的步骤、下次反馈观察项。每个“已写入/已同步/已发布”均附实际证据。
